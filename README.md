# Автоматизация тестирования банковских переводов: BDD (Cucumber), Gherkin и Page Object Model (Java & Gradle)

Продвинутый учебный проект в блоке UI-автоматизации, направленный на изучение методологии разработки и тестирования через поведение — **Behavior Driven Development (BDD)**. В проекте реализована автоматизация сценариев перевода денежных средств между картами пользователя с использованием фреймворка **Cucumber** (язык сценариев Gherkin) и паттерна проектирования **Page Object Model (POM)**.

В данной версии проекта тестовое покрытие было расширено до **валидации негативных сценариев**, что позволило успешно локализовать критический дефект бизнес-логики в тестируемой системе (SUT).

## 🎯 Цели и задачи проекта
* **Изучение BDD и Cucumber**: написание автотестов на декларативном, понятном бизнесу языке Gherkin (сценарии формата *Пусть - Когда - Тогда*).
* **Применение Page Object Model (POM)**: проектирование архитектуры UI-тестов, где каждая страница интернет-банка представлена отдельным Java-классом.
* **Негативное UI/Бизнес-тестирование**: автоматизация проверок на обработку некорректных финансовых операций (перевод сумм, превышающих доступный лимит).
* **Связывание с баг-трекингом**: практика локализации реального бага, блокировки конвейера CI упавшим тестом и документирования дефекта в **GitHub Issues**.

## 📋 Описание автоматизированных BDD-сценариев

Тестируемый сервис содержит одного захардкоженного пользователя с двумя дебетовыми картами без овердрафта. В рамках проекта разработаны и запущены два противоположных сценария:

### 1. Позитивный сценарий (Happy Path)
```gherkin
Сценарий: Успешный перевод денежных средств между собственными картами пользователя
  Пусть пользователь залогинен с именем «vasya» и паролем «qwerty123»
  Когда пользователь переводит 5 000 рублей с карты с номером 5559 0000 0000 0002 на свою 1 карту с главной страницы
  Тогда баланс его 1 карты из списка на главной странице должен стать 15 000 рублей
```

### 2. Негативный сценарий (Валидация лимита)
```gherkin
Сценарий: Отмена перевода при попытке списать сумму, превышающую текущий баланс карты
  Пусть пользователь залогинен с именем «vasya» и паролем «qwerty123»
  Когда пользователь пытается перевести 30 000 рублей с карты с номером 5559 0000 0000 0002 на свою 1 карту с главной страницы
  Тогда система должна заблокировать операцию и отобразить ошибку, а баланс карт должен остаться прежним
```

## 🛑 Обнаруженный дефект (Bug Report)

Благодаря внедрению негативного BDD-сценария, в системе был обнаружен критический баг. Дефект задокументирован в рамках данного репозитория:
* 🔗 **[Подробный Bug Report в GitHub Issues #1](../../issues/1)**

### Суть бага:
При выполнении негативного теста на перевод суммы, превосходящей доступный баланс карты-отправителя, **система ошибочно одобряет транзакцию**. Деньги всё равно переводятся на карту-получатель, в результате чего на дебетовой карте-отправителе (не имеющей функции овердрафта) образуется **негативный (отрицательный) баланс**. 

Автотест зафиксировал расхождение фактического поведения системы с ожидаемой бизнес-логикой и прервал сборку в CI. Падение теста является легитимным и воспроизводит реальную уязвимость банковского функционала.

## 🧠 Архитектура решения и структура Page Objects

Интерфейс интернет-банка декомпозирован на независимые классы страниц, предоставляющие доменные методы:
1. **`LoginPage`** — страница авторизации пользователя (ввод учетных данных `vasya` / `qwerty123`).
2. **`VerificationPage`** — страница подтверждения входа по SMS-коду.
3. **`DashboardPage`** — главная страница (методы получения баланса карт и выбора карты для пополнения).
4. **`TransferPage`** — страница перевода средств (метод заполнения суммы, номера донорской карты и подтверждения транзакции).

## ⚙️ Запуск тестов

Для локального запуска всего пакета тестов выполните команду:
```bash
./gradlew test -Dselenide.headless=true
```
*На текущий момент сборка в **GitHub Actions** и локально падает на негативном сценарии, что наглядно демонстрирует работу автотестов как главного инструмента контроля качества (Quality Gate) перед релизом.*
